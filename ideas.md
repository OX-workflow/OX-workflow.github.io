# ONYX Framework Case Study — Design Direction

## Reference Ground Truth

The supplied ONYX remote-operator screens are the visual ground truth. The public case-study site will transpose their **technical control-room aesthetic** into an editorial, evidence-led project narrative rather than reproduce an internal application UI. Fidelity to the supplied references takes priority over generic landing-page conventions.

## Chosen Approach: Operational Documentation

### Design Movement

An **operational documentation system**: a restrained hybrid of enterprise control-room UI, technical field manual, and systems-architecture case study.

### Core Principles

1. **Authority through structure.** Deep navy structural elements, evidence panels, and precise metadata communicate traceability without promotional excess.
2. **Evidence before assertion.** Repository facts, external references, and explicit boundary diagrams carry the narrative.
3. **Restrained hierarchy.** Large editorial headings sit beside small uppercase context labels; generous space separates concepts rather than decorative effects.
4. **Interfaces as architecture.** Lines, status markers, module blocks, and command-style navigation reinforce IFEM’s emphasis on clear responsibilities.

### Color Philosophy

The visual base is a cool, fogged white workspace framed by an ONYX navy rail. A measured cobalt blue acts as the operative signal, while green and amber only communicate verified methodology and constraints. This keeps the page calm, technical, and legible in both light and dark settings.

### Layout Paradigm

A permanent **documentation rail** on desktop acts as the architectural spine. Content flows in asymmetric editorial bands beside it: oversized introductory copy, two-column evidence modules, and a central layered-system diagram. On small screens, the rail collapses into a compact top bar and the narrative becomes a single disciplined reading column.

### Signature Elements

1. A square ONYX mark set inside a thin outlined frame.
2. Fine technical rules, numbered section indexes, and small capsule metadata labels.
3. Layered diamond planes and connector nodes based on the supplied IFEM mark, used as a quiet diagrammatic motif.

### Interaction Philosophy

Navigation is functional and explicit: active sections are visibly indexed, external evidence links use directional arrows, and dark-mode state is persistent. Interactions provide subtle confirmations, never ornamental distraction.

### Animation

Sections reveal by a short upward fade as they enter the viewport. Diagram lines draw in subtly on initial load, while controls use a fast 160ms press response and a crisp 180ms hover transition. Motion respects reduced-motion preferences.

### Typography System

**Manrope** anchors interface labels, navigation, and metadata with engineered clarity. **DM Sans** carries headings and body text with calm humanist proportions. Headings use tight tracking and substantial weight; metadata is uppercase, widely tracked, and deliberately small.

### Brand Essence

**ONYX Framework is an evidence-led architecture case study for engineers who value explicit interfaces and maintainable system boundaries.**

Personality: **methodical, restrained, inspectable.**

### Brand Voice

Headlines state the architectural subject. CTAs point to evidence rather than conversion.

> “A framework architecture with inspectable boundaries.”

> “Trace the implementation on GitHub.”

### Wordmark & Logo

Use the supplied ONYX visual language: a framed square symbol paired with a spaced uppercase ONYX wordmark. The geometric layers inspired by the supplied IFEM mark become the supporting architectural motif, not a replacement for ONYX.

### Signature Brand Color

**ONYX Navy — #0B284F**. This is the page’s ownable structural color and must anchor navigation, primary actions, and technical linework.
